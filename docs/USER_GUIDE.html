For cleaning up Phyllis's contacts. October 2026 version (v7 + Outlook CSV + any-format loader).

Use the offline copy today, not the website. The newest fixes are in DeDupe Pro (offline).html on your Mac's Desktop. They are the damage warnings and the guard that stops a file with no header row from being misread. 1Safety first, before touching anything

Contacts sync from Outlook through CalDav Synchronizer to the Synology and on to every iPhone and iPad. A mistake in one place spreads everywhere. That is how the notes were lost the first time.

  • Back up Outlook: on the iBuyPower, use File → Open & Export → Import/Export → Export to a file → Outlook Data File (.pst) → pick the contacts folder. Save it to the flash drive with today's date in the name.
  • Pause CalDav Synchronizer on both PCs, the iBuyPower and the Dell. In Outlook, open the CalDav Synchronizer ribbon and turn off auto-sync, or disable the profile. Doing only one PC isn't enough.
  • Find which folder CalDav Synchronizer syncs (open its profile and note the Outlook folder name). That is the folder to export in step 2.
  • Note Outlook's own contact count for that folder (shown at the bottom of the People view). You'll compare against it. It includes contact groups, so expect the app's count to be a little lower.
  • Leave Outlook File for Note Copying.pst alone. It's the pre-dedup snapshot with the original notes.

2Get the contacts out of Outlook

  1. In Outlook: File → Open & Export → Import/Export.
  2. Export to a file → Comma Separated Values → choose the contacts folder from step 1 → Next.
  3. Save it to the flash drive as something like Outlook contacts 2026-10-26.csv, then Finish.
Don't double-click the CSV. On Windows it opens in Excel, and if it's saved again Excel rewrites phone numbers, dates and accents. If that happens, export again. The app warns you if it spots Excel damage.

Other files the app can read if that's what you have: an iPhone or Synology .vcf, a Google Contacts CSV, an Excel .xlsx, or a "Unicode text" export. A .pst needs the Mac converter (section 4).

3Load the file and check it

  1. Open DeDupe Pro (offline).html. Optional: click A A (top right) for larger text and ◑ for a light background.
  2. Drag the CSV onto Main contact file, or click it and choose the file. Nothing is uploaded; the file is read on this computer only.
  3. Check what the box says:
You seeMeaning
Outlook CSV · Windows encoding and 92 of 92 columns recognised (or similar)Ideal. Contacts that aren't merged go back into Outlook exactly as they were exported.
Contacts spreadsheetNot a standard Outlook export (Google, Excel or homemade). It still works; the app rebuilds these rows in Outlook's columns.
N contacts · N with email · N with phone · N with notesThe contact count should be close to Outlook's count from step 1. If "with email" is zero, the email column wasn't recognised. Stop and tell Claude.
⚠ no email / phone / notes column foundThat column wasn't recognised. Nothing is lost (unknown columns are kept), but matching will be weaker.
Pop-up: notes are exactly N characters longThe export probably cut long notes short. Compare one long note in Outlook with the app before going on (step 4 below).
Pop-up: rows don't line up / unclosed quote / damaged by ExcelThe file is damaged. Export it from Outlook again and don't open it in Excel.
  1. Spot-check one long note. Click Just Browse Contacts, search for someone with a long, multi-line note, and compare it with Outlook. If Outlook shows more text, the export lost it before the app saw it. In that case don't continue with this file.

4If the app won't read it: the Mac converter

Use this when the app refuses the file, or when all you have is a .pst. It converts the file on your Mac into a .vcf the app definitely reads. It prints only counts (never names, numbers or notes), so it's safe to have Claude run it for you.

Ask Claude: "Run the contact converter on the file at <path>". Or run it yourself in Terminal:

cd "~/MHN1 Dropbox/Philip King/Mac/Documents/Apps/DeDupe Pro copy"
node tools/convert-contacts.mjs "/Volumes/FLASHDRIVE/Outlook contacts 2026-10-26.csv"
  • It writes ….CONVERTED.vcf and ….CONVERTED-for-Outlook.csv next to the original. Load the .vcf into the app.
  • Both "Re-read check" lines should say OK.
  • .pst files: quit Outlook first (Outlook locks the file), or work on a copy. This path hasn't been tested on a real .pst yet, so compare the counts with Outlook.
  • If it says FAILED with hidden details, run it yourself with --debug on the end to see the error. Do this in your own Terminal, because that output may show contact data.

5Review the duplicates

  1. Leave the setting at Balanced 60% and click Find Duplicates.
  2. Groups that are 95% or more and have no warnings are already marked Will merge (pre-approved). Everything else waits for you.
  3. Set the status filter to Needs decision. Work through the 95–100% tab first, then the lower ones.
  4. Click a group to open it. For each one:
    • Name to keep: click the spelling you want, such as "Nellie Boykoff" rather than "Nurse X and Nellie Boykoff". The other spellings are saved in the notes.
    • ✖ Not a dupe (on one card, in groups of 3 or more): takes that card out of the group.
    • ✔ Merge: combine them. ✖ Skip: keep them separate. ✏ Edit: fix a field. The edit box only closes with Cancel, Save or Esc.
    • ↩ Undo (top) reverses the last action.
  5. The green line under the merged preview, "Notes: N chars kept of N", confirms no note text is lost.
  6. Groups with warnings need a person's judgement, especially "Different organizations". Phyllis sometimes files a nurse or office under the doctor's name on purpose.
  7. The lower tiers are mostly not duplicates: households sharing a phone, CPMC departments, 800 numbers. Skip is usually right there.
Progress saves itself in this browser. If the tab closes, load the same file with the same settings and click Find Duplicates; it offers to pick up where you left off. On Phyllis's PC, that saved progress stays in Firefox on her machine.

6Download the results

Click Export Clean Contacts. Check that Note integrity and Field integrity both say OK, then download:

  • Clean contacts for Outlook (.csv): same columns as her export, ready for Outlook.
  • Clean contacts (.vcf): for the Synology, iPhone or Mac.
  • Audit log: which cards were merged into which. Keep it.
  • Duplicate list (.txt): a printable list of every group, the one Phyllis asked for.

Save everything to the flash drive, next to the original export and the .pst backup.

7Putting it back into Outlook (carefully)

Today: test only. Don't replace her live contacts. Importing the clean file over the synced folder either doubles every contact on every device ("Allow duplicates") or leaves the merged-away duplicates behind ("Replace"). Swapping folders gives every contact a new identity, which breaks iPhone Favorites.
  1. In Outlook, make a new contacts folder that CalDav Synchronizer does not sync, for example "Clean test 2026-10-26".
  2. File → Open & Export → Import/Export → Import from another program or file → Comma Separated Values → choose the clean CSV → Do not import duplicate items → import into the new folder.
  3. Check the count, a few long notes, and an accented name. If accents look wrong, tell Claude; it may need a different encoding.
  4. Next visit, not today:
    • Send 5 test contacts through the full chain: Outlook → Synology → iPhone.
    • Practise restoring from the .pst backup.
    • Only then plan the switch-over, with CalDav Synchronizer paused on both PCs.
  5. When you're done, turn CalDav Synchronizer back on for both PCs.

8Comparing two lists (Outlook vs iPhone or Synology)

  1. Clean each list on its own first (sections 3–6).
  2. Load one in Main contact file and the other in Second file. Tick only look for duplicates between the files, then click Find Duplicates.
  3. The export screen offers Only in "iPhone" and Only in "Outlook" downloads, as an Outlook .csv or a .vcf. These are the contacts the other list is missing, such as new patients added on the phone.

This comparison also catches characters lost in Outlook's export. Its default "Windows" encoding can turn emoji and non-Latin names into "?". If an Outlook contact shows "?" where the iPhone copy has the real character, trust the iPhone copy.

9Troubleshooting

ProblemWhat to do
"Couldn't find a header row…"The file has no column headings, or it isn't a contacts export. Export again from Outlook (section 2), or use the Mac converter.
"This is an Outlook data file (.pst)"Export a CSV instead, or use the Mac converter on the .pst with Outlook closed.
Excel file won't loadReading Excel files needs internet once. Without internet, in Excel use Save As → "CSV UTF-8 (Comma delimited)" and load that.
Count far lower than Outlook'sCheck whether the right folder was exported, and whether there's a warning about rows not lining up. Contact groups aren't counted.
Blank page on Phyllis's PCFirefox is too old. Update Firefox, or use the Mac.
Export says note integrity has issuesAn edited group has shorter notes than the originals. Search for the name in Review, then fix or Skip it.

10Never do this

  • Never double-click a .vcf on the Mac: it imports every contact into Contacts. Never double-click a .csv on Windows: it opens in Excel.
  • Never edit contacts in the Synology Contacts web page (DSM); it can damage data.
  • Never import into the live, synced folder, and never run the cleanup on two PCs at once.
  • Never paste contact data into a chat with Claude. The converter is built so Claude only ever sees counts.
  • Don't git push the project. The GitHub repo is public, and the test files still contain a few real-looking names.
